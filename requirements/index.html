系列全链路诊断看板需求文档

1. 背景与目标

本看板用于诊断一个商品系列在抖音经营链路中的健康度。这里的诊断对象是“系列”，例如吾跃系列、菲林系列，而不是单个 SKU。

看板目标不是复刻 Excel，而是把数据分析师整理的诊断模型产品化，让运营、投放、内容、商品团队能快速回答三个问题：

  • 这个系列当前全链路是否健康？
  • 问题主要出在哪个链路和哪个指标？
  • 对应的诊断结论和建议动作是什么？

默认诊断链路为：

营销端 → 搜索心智承接 → EC承接 → 口碑售后

2. 全局页面规则

2.1 全局筛选项

顶部全局筛选区保留四个筛选项：

  • 系列
  • 细分系列
  • 时间范围
  • 对比口径

不提供“渠道”和“内容类型”筛选。原因是渠道、触点、来源在各专题页中都是对比行或拆解维度，不是全局过滤条件。筛掉某个渠道会破坏横向比较。

细分系列用于在大系列下继续选择子系列，例如吾跃轻量跑鞋、吾跃通勤训练、吾跃缓震进阶。该筛选只改变诊断对象范围，不代表 SKU 下钻。

2.2 状态枚举

指标业务状态统一为三类：

  • 正常
  • 预警
  • 异常

不使用单纯的 ✅ / ❌ 作为最终状态展示。

另外允许存在数据质量状态：

  • 缺失

“缺失”不是业务健康状态，不参与健康度评分，也不进入 Top 5。页面可在指标值位置展示 --，并通过数据质量信息说明缺失原因。

2.3 时间范围与基准值

V1 时间范围按周开发，不使用“近 7 天 / 近 30 天 / 近 90 天”作为主筛选。

时间筛选示例：

  • 2026-W18
  • 2026-W19
  • 2026-W20
  • 2026-W21

周口径按自然周或业务周执行，需在数据接口中固定定义。页面只展示可选周，不在前端自行计算周范围。

第一版默认基准值为：

前 4 周平均值

后续可以支持切换为上周期、目标值等口径，但页面状态判断必须基于当前选择的对比口径。

2.4 环比变化单位

环比变化不强行统一单位，而是按指标类型展示：

  • 金额、人数、次数、数量类指标：使用 %
  • 转化率、占比、退货率、好评率等比率类指标：使用 pp

示例：

  • 内容曝光量：-18.4%
  • 商品点击率：-2.3pp
  • 退货率：-0.7pp
  • 内容曝光量占比、内容互动量占比、新发布内容占比等“占比类指标”的变化统一使用 pp

3. 健康度评分逻辑

3.1 总体原则

健康度评分用于快速表达系列或某个链路的整体风险水平。评分不是业务目标值，而是由指标状态和指标权重计算出的诊断分。

评分范围：

0 - 100

分数越高表示越健康。

3.2 单指标得分

每个指标先根据状态转换为单指标得分：

状态 单指标得分
正常 100
预警 60
异常 20

如果指标缺失或无法计算，第一版不纳入评分，并在数据质量层标记为“缺失”。不要默认按 0 分处理，避免误伤健康度。

3.3 链路健康度得分

每个链路按该链路的核心指标加权计算。

计算公式：

链路健康度 = Σ(指标得分 × 指标权重) / Σ(指标权重)

V1 规则：链路内部的核心指标使用等权重。后续如果业务确认不同指标影响不同，可按指标重要度配置权重。

示例：

营销端核心指标包括：

  • 营销花费
  • 千川花费占比
  • 营销ROI
  • 内容曝光量
  • 付费曝光占比
  • 有曝光内容数
  • 新发布内容占比
  • UGC占比
  • 篇均曝光量
  • 篇均互动量

因此 V1 中，营销端健康度为这些指标得分的平均值。搜索心智承接、EC承接、口碑售后同理，均先按链路内部指标等权重计算。

3.4 全链路健康度得分

全链路健康度由四个链路健康度加权计算：

全链路健康度 = 营销端得分 × 30%
             + 搜索心智承接得分 × 25%
             + EC承接得分 × 30%
             + 口碑售后得分 × 15%

V1 全链路权重：

链路 权重 理由
营销端 30% 前置声量决定后续搜索和成交基础
搜索心智承接 25% 判断内容是否形成主动搜索和搜索成交
EC承接 30% 直接影响销售转化和 GMV
口碑售后 15% 影响长期信任和转化，但通常滞后于前链路

说明：V1 并不是全链路四段等权重，而是“链路内部指标等权重 + 链路之间按 30/25/30/15 加权”。权重后续应支持配置化。

3.5 分数对应状态

健康度分数 状态
≥ 80 正常
≥ 60 且 < 80 预警
< 60 异常

4. 指标状态判断逻辑

4.1 基础判断方式

每个指标都需要配置：

  • 指标方向
  • 预警阈值
  • 异常阈值
  • 诊断结论
  • 建议动作

指标方向分为两类：

  • 正向指标：越高越好，例如内容曝光量、搜索成交金额、商品点击率、好评率、产品词搜索GPMS
  • 反向指标：越低越好，例如退货率、差评率、CPM

4.2 正向指标状态判断

适用于越高越好的指标。

达成率 = 当前值 / 基准值

建议第一版规则：

达成率 状态
≥ 100% 正常
≥ 85% 且 < 100% 预警
< 85% 异常

4.3 反向指标状态判断

适用于越低越好的指标。

超标率 = 当前值 / 基准值

建议第一版规则：

超标率 状态
≤ 100% 正常
> 100% 且 ≤ 115% 预警
> 115% 异常

4.4 特殊指标

部分指标不适合用统一阈值，需要单独配置规则，例如：

  • ROI
  • 内容触达搜索率
  • 新发布内容占比
  • 搜索商品点击成交率

这些指标仍使用“正常 / 预警 / 异常”三态，但阈值应来自指标规则库。

产品词搜索GPMS 不作为特殊指标处理。它的定义是“产品词千次搜索成交金额”，属于越高越好的正向指标，直接使用 4.2 的正向指标状态判断规则。

V1 默认阈值如下，用于开发和测试验证：

特殊指标 指标方向 正常 预警 异常
直接支付ROI 越高越好 当前值 ≥ 基准值 当前值 ≥ 基准值 × 85% 且 < 基准值 当前值 < 基准值 × 85%
内容触达搜索率 越高越好 当前值 ≥ 基准值 当前值 ≥ 基准值 × 70% 且 < 基准值 当前值 < 基准值 × 70%
新发布内容占比 越高越好 当前值 ≥ 基准值 当前值 ≥ 基准值 × 70% 且 < 基准值 当前值 < 基准值 × 70%
搜索商品点击成交率 越高越好 当前值 ≥ 基准值 当前值 ≥ 基准值 × 85% 且 < 基准值 当前值 < 基准值 × 85%
搜索-成交率 越高越好 当前值 ≥ 基准值 当前值 ≥ 基准值 × 85% 且 < 基准值 当前值 < 基准值 × 85%

5. 诊断结论与建议动作

5.1 来源

诊断结论和建议动作必须来自数据分析师原表中的诊断规则，不允许页面自行生成“低于基准”这类无行动价值的描述。

0614 版规则库来源：

  • Excel 文件：单品全链路诊断看板梳理0614版本.xlsx
  • 总览规则主表：总看板—单品全链路诊断概览
  • 规则列：第 4 行表头中的 关键指标、诊断结论（未达标时）、建议动作
  • 规则范围：第 5 行至第 33 行的全链路核心指标
  • 分看板辅助判断：各分看板中的 快速诊断 / 诊断结论 列，用于专题页模块内的判断文案

开发落库时应将 Excel 中的规则整理为 metricRules，由接口返回给前端。前端不硬编码诊断结论和建议动作。

总览核心规则示例与落库口径如下：

指标 诊断结论 建议动作
营销花费 投入不足或效率低下，导致声量/曝光无法支撑转化目标 增加营销花费，提升渠道效率
内容曝光量 品牌/产品在抖音的声量不足或触达效率低 增加投流预算、增加达人合作数量、提高发布频次
有曝光内容数 内容资产少，依赖少数爆文 批量生产混剪、多账号分发，每周上新 N 条
新发布内容占比 内容老化，缺乏新鲜度 制定内容日历强制周更、蹭热点话题快速出片
UGC占比 自然内容占比过低，依赖付费 发起UGC话题挑战、激励用户投稿、置顶优质UGC
篇均曝光量 内容分发效率低 优化前3秒完播率、修改标题/封面、增加利益点
篇均互动量 内容吸引力差，用户点赞/评论/转发的意愿低 分析高互动竞品、重构内容钩子（悬念/槽点/福利）、增加引导CTA
产品词搜索次数 用户主动搜索意愿低，品牌/产品心智弱 视频强化小蓝词配置，评论区官旗评论引导
产品词搜索成交金额 搜索流量未有效转化为成交 检查是搜索量不足还是转化率低
产品词搜索成交率 搜索进店后转化差，商品页或价格缺乏竞争力 优化产品主图/标题/价格/评论首屏/核心卖点
产品词搜索GPMS 搜索流量价值低 优化搜索结果页主图+优惠、投放搜索卡位
内容触达搜索率 看了内容的人不去搜索，内容种草力弱或引导缺失 视频强化小蓝词配置，评论区官旗评论引导
直播间产品讲解时长 产品曝光机会不足，主播未给足产品讲解时间 增加产品讲解时长占比，设置讲解提醒/考核
商品曝光人数 商品卡片/详情页获流能力弱 提升直播的讲解时长、调整商品在购物车的顺序，增加商城频道各活动板块的参与度
商品点击人数 商品详情页引流绝对人数不足 提升曝光位置+增加内容挂载+优化点击率+广告引流
商品购买人数 最终成交人数未达标 优先解决点击人数不足，或优化详情页转化+促销+追投
内容->商品曝光率 看了内容的人不点商品页，商品入口埋点不足 视频加商品锚点/弹窗、评论区挂链接，小蓝词维护
商品点击率 商品卡吸引力差（主图/价格/标题/销量） 商品头图、标题优化；直播间话术引导商品点击或浏览购物车点击商品
商品购买率 详情页信任或价格/优惠有问题 重点加强用户点击后的转化行为，注意营销机制和商品库存，加强逼单话术，提升商品成交；强化价格优势，优化评论和详情页等提升用户转化
商品销售金额 整体生意目标是否达成 把握核心渠道成交的同时，渗透其他场景
退货金额 售后成本过高，侵蚀利润 下钻到「售后看板」分析退货原因，针对性改善
退货率 产品体验或描述不符严重 优化详情页描述，避免夸大；加强品控；发货前增加确认环节
评论数 用户参与反馈少，缺少社交证明 发起“评论抽奖”或“晒图返现”、客服主动邀请评论
差评率 用户负面反馈多，影响转化和品牌形象 优化详情页描述，避免预期落差；基于差评词云，驱动产品改进

说明：

  • 0614 总览表中部分新增计算字段只提供指标定义，未单独填写诊断结论和建议动作时，开发不得自行生成文案，应按规则库配置结果展示为空或使用同一诊断维度下已配置的规则，具体以数据规则表落库结果为准。
  • 分看板中的 快速诊断 是专题页模块判断文案，不等同于总览 Top 5 的建议动作。

5.2 触发方式

当指标状态为“预警”或“异常”时，展示对应诊断结论和建议动作。

当指标状态为“正常”时，可以展示简短说明，但不进入待处理问题列表。

6. 总览页需求

6.1 页面目标

总览页用于回答：

  • 当前系列全链路是否健康？
  • 最应该优先处理哪些问题？

6.2 页面模块

总览页包含：

  1. 当前诊断对象
  2. 全链路健康度评分
  3. 四段链路状态
  4. 待处理问题 Top 5
  5. 选中问题诊断卡
  6. 核心指标矩阵
  7. 商品人群画像差异

6.3 当前诊断对象

仅展示：

  • 系列名称
  • 商品数
  • 覆盖类目

不展示商品图、SKU、货号、主推商品数、当前诊断周期。

6.4 待处理问题 Top 5

Top 5 只展示状态为“预警”或“异常”的指标。

正常指标不进入 Top 5。

建议排序公式：

问题优先级分 = 状态严重度 × 偏离程度 × 业务影响权重 × 链路前置权重

建议默认规则：

  • 异常优先于预警
  • 偏离基准越大优先级越高
  • 越靠前链路的问题优先级越高
  • 直接影响成交或销售的指标优先级更高

6.5 选中问题诊断卡

右侧诊断卡展示当前选中的 Top 问题，不是独立信息区。

展示内容：

  • 异常指标
  • 当前值 vs 基准值
  • 诊断结论
  • 建议动作
  • 下钻入口

6.6 核心指标矩阵

核心指标矩阵是总览页的全链路体检底表。

字段：

  • 环节
  • 关键指标
  • 当前值
  • 基准值
  • 环比变化
  • 状态
  • 诊断结论
  • 建议动作

Top 5 从核心指标矩阵中的异常/预警项计算得出。

0614 版总览核心指标矩阵需补充以下营销端指标：

  • 千川花费占比：千川花费（千川推直播间 + 千川推商品） / 营销总花费
  • 营销ROI：商品消耗金额 / 营销花费
  • 付费曝光占比：（除企业号视频、自然内容曝光量之和） / 内容曝光量
  • UGC占比：自然内容曝光量 / 总内容曝光量

6.7 商品人群画像诊断

该模块用于比较不同链路人群是否一致，帮助判断“曝光、全域内容观看、非自然内容观看、购买是否来自同一类人群”。V1 不再使用自然语言逐行诊断，直接展示原始占比、购买人群与其他人群的占比差值，以及整体人群相似度。

横向展示四类链路人群：

  • 商品购买人群
  • 商品曝光人群
  • 商品全域内容观看人群
  • 商品非自然内容观看人群

V1 必须使用完整诊断表展示，不使用摘要卡片替代表格。字段如下：

  • 人群分类
  • 人群标签
  • 商品购买人群
  • 商品曝光人群
  • 商品购买-曝光人群差异
  • 商品全域内容观看人群
  • 商品购买-内容观看人群差异
  • 商品非自然内容观看人群
  • 商品购买-非自然内容观看人群差异

差异列计算规则：

商品购买-曝光人群差异 = 商品购买人群占比 - 商品曝光人群占比
商品购买-内容观看人群差异 = 商品购买人群占比 - 商品全域内容观看人群占比
商品购买-非自然内容观看人群差异 = 商品购买人群占比 - 商品非自然内容观看人群占比

差异列单位统一使用 pp。例如：商品购买人群 59%，商品曝光人群 54%，则商品购买-曝光人群差异为 +5pp。

差异列展示规则：当差异绝对值大于 10pp 时，页面需用红色字体高亮；+10pp 或 -10pp 不触发高亮。

人群相似度计算规则参照 Excel 原表公式，使用购买人群占比向量与对比人群占比向量的余弦相似度：

人群相似度(购买, X)
= SUMPRODUCT(购买人群占比向量, X 人群占比向量)
  / (SQRT(SUMPRODUCT(购买人群占比向量 ^ 2)) * SQRT(SUMPRODUCT(X 人群占比向量 ^ 2)))

其中 X 分别为商品曝光人群、商品全域内容观看人群、商品非自然内容观看人群。若分母为 0 或计算异常，则按 Excel IFERROR(..., 0) 逻辑返回 0。

V1 相似度展示：

  • 购买 vs 曝光人群相似度
  • 购买 vs 内容观看人群相似度
  • 购买 vs 非自然内容观看人群相似度

相似度计算使用表格中的完整人群标签向量，不按单个人群分类拆开计算。

数据口径：

  • 商品购买人群：完成购买该系列商品的人群。
  • 曝光人群：系列相关内容或商品曝光覆盖的人群。
  • 商品全域内容观看人群：系列相关内容产生有效观看的人群。
  • 商品非自然内容观看人群：商品全域内容观看人群中排除自然内容后的内容观看人群。

人群分类与标签对齐原表，至少包含：

  • 性别：男性、女性
  • 年龄：18-23、24-30、31-40、41-50、50+
  • 消费等级：低消费、中消费、高消费
  • 地域：东北、华北、华东、华南、华中、西北、西南、其他
  • 八大快消人群：genz、都市蓝领、都市银发、精致妈妈、小镇青年、小镇中老年、新锐白领、资深中产

差异解释方式：

  • 以商品购买人群作为目标人群基准。
  • 正值表示购买人群在该标签上的占比高于对比链路人群。
  • 负值表示购买人群在该标签上的占比低于对比链路人群。
  • 页面不再逐行生成自然语言诊断，避免结论过重；运营可根据差值和相似度判断是哪类人群出现偏差。

V1 不做具体 SKU 下钻，仅在系列/细分系列维度展示人群差异。

13. 开发交付必须补齐的数据契约

13.1 总体数据结构

前端不应自行推导业务结论。接口或数据层需要返回以下结构，前端负责展示和交互：

dashboardData = {
  filters,
  overview,
  marketing,
  search,
  ec,
  service,
  metricRules,
  dataQuality
}

每个指标对象至少包含：

metric = {
  metricCode,        // 稳定编码
  metricName,        // 展示名称
  link,              // 所属链路：marketing/search/ec/service
  module,            // 所属模块
  currentValue,      // 当前值，原始数值
  currentDisplay,    // 当前值展示文本
  baselineValue,     // 基准值，原始数值
  baselineDisplay,   // 基准值展示文本
  changeValue,       // 环比或差值，原始数值
  changeDisplay,     // 展示文本，% 或 pp
  direction,         // positive / negative / custom
  status,            // 正常 / 预警 / 异常；数据缺失时为缺失
  diagnosis,         // 诊断结论，来自规则库
  action,            // 建议动作，来自规则库
  drilldownPage      // 可下钻页面
}

13.2 计算责任边界

推荐后端或数据服务完成以下计算：

  • 当前值、基准值、环比变化
  • 指标状态
  • 单指标得分
  • 链路健康度
  • 全链路健康度
  • Top 5 待处理问题排序
  • 人群相似度

前端可以在本地做展示态计算，例如格式化、排序后的渲染、chip 切换和表格横向滚动，但不应在前端硬编码业务阈值和诊断结论。

13.3 缺失值、0 基准值和异常值处理

为避免开发时出现各端口径不一致，V1 统一按以下规则处理：

  • currentValue 缺失：指标状态为“缺失”，不进入健康度评分，不进入 Top 5。
  • baselineValue 缺失：指标状态为“缺失”，不进入健康度评分，不进入 Top 5。
  • baselineValue = 0 且没有单独指标规则：不做当前值 / 基准值计算，状态为“缺失”。
  • currentValue = 0 且 baselineValue > 0：按正常正向/反向指标规则计算。
  • 分母为 0 的人群相似度：按 Excel IFERROR(..., 0) 返回 0。
  • 页面展示缺失值时使用 --，并在数据质量字段中返回缺失原因。

13.4 数据质量字段

接口需要提供数据质量信息，至少包含：

dataQuality = {
  missingMetrics: [],
  staleMetrics: [],
  lastUpdatedAt,
  warnings: []
}

其中：

  • missingMetrics：缺失指标列表。
  • staleMetrics：数据未按当前周更新的指标列表。
  • lastUpdatedAt：数据更新时间。
  • warnings：例如“营销端细分系列使用大系列数据”等口径提示。

口径提示只用于必要的数据说明，不展示实现说明型文案。

15. 页面展示验收标准

15.1 全局验收

  • 全局筛选只包含系列、细分系列、时间范围、对比口径。
  • 不出现全局渠道筛选、内容类型筛选。
  • 时间范围按周展示。
  • 指标业务状态只使用正常、预警、异常；数据质量状态允许缺失。
  • 正常指标不进入待处理问题 Top 5。
  • 诊断结论和建议动作必须来自规则库，不展示“低于基准”“高于基准”这类无行动价值描述。

15.2 总览页验收

  • 当前诊断对象只展示系列名称、商品数、覆盖类目。
  • 核心指标矩阵包含当前值、基准值、环比、状态、诊断结论、建议动作。
  • Top 5 从核心指标矩阵的预警/异常项中生成。
  • 点击 Top 5 问题后，右侧诊断卡同步切换。
  • 点击下钻入口后进入对应专题页。
  • 人群画像差异列按 购买人群占比 - 对比人群占比 展示，单位为 pp。
  • 人群差异绝对值 > 10pp 时红色高亮，= 10pp 不高亮。
  • 人群相似度按完整标签向量计算，不按单个人群分类拆开计算。

15.3 分看板验收

  • 营销端按 核心KPI → 投资结构 → 内容结构与来源 → 内容质量 → 内容老化 → 明细 展示。
  • 营销端内容明细支持 CSV 导出。
  • 搜索承接不新增渠道或内容类型筛选，触点作为表格行展示。
  • 产品词搜索GPMS 按正向指标处理。
  • EC 分渠道转化漏斗必须展示指标、当前值、环比、基准值、状态、判断。
  • 口碑售后退货大类和具体原因通过 chip 切换，不在同一张图混合。
  • 无汇总数据时，趋势图不展示“全部”chip。

15.4 文案验收

  • 页面文案面向品牌方阅读，不展示实现说明。
  • 不展示“点击 chip 切换”“页面只负责”“字段对齐原表”等内部说明。
  • 需要说明数据口径时，只展示对业务理解有帮助的说明，例如“营销端细分系列使用大系列数据”。

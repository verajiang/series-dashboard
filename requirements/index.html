系列全链路诊断看板需求文档

1. 背景与目标

本看板用于诊断一个商品系列在抖音经营链路中的健康度。这里的诊断对象是"系列"，例如吾跃系列、菲林系列，而不是单个 SKU。

看板目标不是复刻 Excel，而是把数据分析师整理的诊断模型产品化，让运营、投放、内容、商品团队能快速回答三个问题：

  • 这个系列当前全链路是否健康？
  • 问题主要出在哪个链路和哪个指标？
  • 对应的诊断结论和建议动作是什么？

默认诊断链路为：

营销端 → 搜索心智承接 → EC承接 → 口碑售后

2. 全局页面规则

2.1 全局筛选项

顶部全局筛选区只保留三个筛选项：

  • 系列
  • 时间范围
  • 对比口径

不提供"渠道"和"内容类型"筛选。原因是渠道、触点、来源在各专题页中都是对比行或拆解维度，不是全局过滤条件。筛掉某个渠道会破坏横向比较。

2.2 状态枚举

所有指标状态统一为三类：

  • 正常
  • 预警
  • 异常

不使用单纯的 ✅ / ❌ 作为最终状态展示。

2.3 基准值

第一版默认基准值为：

前 4 周平均值

后续可以支持切换为上周期、目标值等口径，但页面状态判断必须基于当前选择的对比口径。

2.4 环比变化单位

环比变化不强行统一单位，而是按指标类型展示：

  • 金额、人数、次数、数量类指标：使用 %
  • 转化率、占比、退货率、好评率等比率类指标：使用 pp

示例：

  • 内容曝光量：-18.4%
  • 商品点击率：-2.3pp
  • 退货率：-0.7pp

3. 健康度评分逻辑

3.1 总体原则

健康度评分用于快速表达系列或某个链路的整体风险水平。评分不是业务目标值，而是由指标状态和指标权重计算出的诊断分。

评分范围：

0 - 100

分数越高表示越健康。

3.2 单指标得分

每个指标先根据状态转换为单指标得分：

状态单指标得分
正常100
预警60
异常20

如果指标缺失或无法计算，第一版不纳入评分，并在数据质量层标记为"缺失"。不要默认按 0 分处理，避免误伤健康度。

3.3 链路健康度得分

每个链路按该链路的核心指标加权计算。

计算公式：

链路健康度 = Σ(指标得分 × 指标权重) / Σ(指标权重)

第一版可先使用等权重。后续如果业务确认不同指标影响不同，可按指标重要度配置权重。

示例：

营销端核心指标包括：

  • 营销花费
  • 内容曝光量
  • 有曝光内容数
  • 新发布内容占比
  • UGC占比
  • 篇均曝光量
  • 篇均互动量

若使用等权重，则营销端健康度为这些指标得分的平均值。

3.4 全链路健康度得分

全链路健康度由四个链路健康度加权计算：

全链路健康度 = 营销端得分 × 30%
             + 搜索心智承接得分 × 25%
             + EC承接得分 × 30%
             + 口碑售后得分 × 15%

建议第一版权重：

链路权重理由
营销端30%前置声量决定后续搜索和成交基础
搜索心智承接25%判断内容是否形成主动搜索和搜索成交
EC承接30%直接影响销售转化和 GMV
口碑售后15%影响长期信任和转化，但通常滞后于前链路

权重后续应支持配置化。

3.5 分数对应状态

健康度分数状态
≥ 80正常
≥ 60 且 < 80预警
< 60异常

4. 指标状态判断逻辑

4.1 基础判断方式

每个指标都需要配置：

  • 指标方向
  • 预警阈值
  • 异常阈值
  • 诊断结论
  • 建议动作

指标方向分为两类：

  • 正向指标：越高越好，例如内容曝光量、搜索成交金额、商品点击率、好评率
  • 反向指标：越低越好，例如退货率、差评率、CPM

4.2 正向指标状态判断

适用于越高越好的指标。

达成率 = 当前值 / 基准值

建议第一版规则：

达成率状态
≥ 100%正常
≥ 85% 且 < 100%预警
< 85%异常

4.3 反向指标状态判断

适用于越低越好的指标。

超标率 = 当前值 / 基准值

建议第一版规则：

超标率状态
≤ 100%正常
> 100% 且 ≤ 115%预警
> 115%异常

4.4 特殊指标

部分指标不适合用统一阈值，需要单独配置规则，例如：

  • ROI
  • GPMS
  • 内容触达搜索率
  • 新发布内容占比
  • 搜索商品点击成交率

这些指标仍使用"正常 / 预警 / 异常"三态，但阈值应来自指标规则库。

5. 诊断结论与建议动作

5.1 来源

诊断结论和建议动作必须来自数据分析师原表中的诊断规则，不允许页面自行生成"低于基准"这类无行动价值的描述。

示例：

指标诊断结论建议动作
内容曝光量品牌/产品在抖音的声量不足或触达效率低增加投流预算、增加达人合作数量、提高发布频次
有曝光内容数内容资产少，依赖少数爆文批量生产混剪、多账号分发，每周上新 N 条
新发布内容占比内容老化，缺乏新鲜度制定内容日历强制周更、蹭热点话题快速出片
产品词搜索GPMS搜索流量价值低优化搜索结果页主图+优惠、投放搜索卡位
商品点击率商品卡吸引力差（主图/价格/标题/销量）商品头图、标题优化；直播间话术引导商品点击或浏览购物车点击商品

5.2 触发方式

当指标状态为"预警"或"异常"时，展示对应诊断结论和建议动作。

当指标状态为"正常"时，可以展示简短说明，但不进入待处理问题列表。

6. 总览页需求

6.1 页面目标

总览页用于回答：

  • 当前系列全链路是否健康？
  • 哪个链路有问题？
  • 最应该优先处理哪些问题？

6.2 页面模块

总览页包含：

  1. 当前诊断对象
  2. 全链路健康度评分
  3. 四段链路状态
  4. 待处理问题 Top 5
  5. 选中问题诊断卡
  6. 核心指标矩阵
  7. 商品人群画像差异

6.3 当前诊断对象

仅展示：

  • 系列名称
  • 商品数
  • 覆盖类目

不展示商品图、SKU、货号、主推商品数、当前诊断周期。

6.4 待处理问题 Top 5

Top 5 只展示状态为"预警"或"异常"的指标。

正常指标不进入 Top 5。

建议排序公式：

问题优先级分 = 状态严重度 × 偏离程度 × 业务影响权重 × 链路前置权重

建议默认规则：

  • 异常优先于预警
  • 偏离基准越大优先级越高
  • 越靠前链路的问题优先级越高
  • 直接影响成交或销售的指标优先级更高

6.5 选中问题诊断卡

右侧诊断卡展示当前选中的 Top 问题，不是独立信息区。

展示内容：

  • 异常指标
  • 当前值 vs 基准值
  • 诊断结论
  • 建议动作
  • 下钻入口

6.6 核心指标矩阵

核心指标矩阵是总览页的全链路体检底表。

字段：

  • 环节
  • 关键指标
  • 当前值
  • 基准值
  • 环比变化
  • 状态
  • 诊断结论
  • 建议动作

Top 5 从核心指标矩阵中的异常/预警项计算得出。

7. 营销端分看板需求

7.1 页面目标

营销端用于回答：

内容声量为什么不够，问题出在投放、内容数量、内容质量，还是内容更新节奏？

7.2 看数路径

核心KPI → 内容营销投资情况 → 内容结构与来源 → 内容质量 → 内容老化 → 内容数据明细

7.3 页面模块

  1. 营销端健康度
  2. 当前核心判断
  3. 核心 KPI 卡片
  4. 内容营销投资情况
  5. 内容结构与来源分析
  6. 内容质量
  7. 内容老化分析
  8. 内容数据明细

7.4 趋势图规则

营销端各分析模块右侧均需要趋势图。

趋势图通过 chip 切换具体渠道或来源，不提供"全部"chip，因为没有汇总线口径。

7.5 内容数据明细导出

内容数据明细默认折叠，支持导出 CSV。

字段对齐原表：

  • 渠道
  • 有曝光内容数
  • 新发布内容数
  • 新发布内容数占比
  • 内容曝光量
  • 内容曝光量占比
  • 内容互动量
  • 内容互动量占比
  • 消耗金额
  • CPM
  • 直接成交金额
  • 直接支付ROI

8. 搜索承接分看板需求

8.1 页面目标

搜索承接用于回答：

  • 用户是否看了内容后主动搜索？
  • 搜索后是否有效成交？
  • 哪些搜索词和触点带动搜索或拖累转化？

8.2 看数路径

核心KPI → 搜索趋势 → 本系列 vs 竞品 → TOP搜索词 → 搜索引流触点 → 搜后转化

8.3 页面模块

  1. 搜索承接健康度
  2. 当前核心判断
  3. 核心 KPI 卡片
  4. 搜索趋势
  5. 本系列 vs 竞品搜索心智承接情况对比
  6. TOP20 产品搜索词监控
  7. 核心搜索引流触点
  8. 搜后转化分析

8.4 不应新增的内容

不增加原表没有的内容类型筛选。

触点是表格行，不是全局筛选项。

9. EC承接分看板需求

9.1 页面目标

EC承接用于回答：

  • 商品流量够不够？
  • 商品点击、加购、购买漏斗卡在哪里？
  • 是整体性问题，还是某个渠道的问题？

9.2 看数路径

核心KPI → 生意渠道贡献 → 整体转化漏斗 → 分渠道转化漏斗

9.3 页面模块

  1. EC承接健康度
  2. 当前核心判断
  3. 核心 KPI 卡片
  4. 生意渠道贡献
  5. 转化漏斗分析
  6. 分渠道转化漏斗

9.4 分渠道转化漏斗字段

分渠道转化漏斗必须展示：

  • 指标
  • 当前值
  • 环比
  • 基准值
  • 状态

不允许只展示指标名称，避免用户第一屏看不到数值。

10. 口碑售后分看板需求

10.1 页面目标

口碑售后用于回答：

  • 用户是否满意？
  • 售后是否侵蚀利润？
  • 退货主要发生在哪个阶段和原因？

10.2 看数路径

核心KPI → 差评原因 → 退货原因

10.3 页面模块

  1. 口碑售后健康度
  2. 当前核心判断
  3. 核心 KPI 卡片
  4. 差评原因分析
  5. 退货原因分析

10.4 维度限制

口碑售后只使用原表中的评论、差评标签、退货原因分类、具体原因等字段。

不新增渠道、内容来源、触点等维度。

10.5 退货原因图表

退货大类和具体原因是两套不同维度，不能混在同一张饼图。

图表需要提供 chip 切换：

  • 退货大类
  • 具体原因

默认展示"退货大类"。

11. 交互需求

11.1 导航

左侧导航包含：

  • 总览
  • 营销端
  • 搜索承接
  • EC承接
  • 口碑售后

点击导航后，顶部标题和副标题同步切换。

11.2 下钻

总览页中的链路卡片和 Top 问题支持点击进入对应专题页。

11.3 趋势图 chip

趋势图 chip 用于切换具体渠道、来源、触点、搜索词或漏斗口径。

没有汇总数据时，不展示"全部"chip。

11.4 明细导出

营销端内容数据明细支持导出 CSV。

导出文件名：

营销端内容数据明细.csv

12. 数据与规则配置建议

建议后续将诊断模型配置化，至少包含：

  • 指标编码
  • 指标名称
  • 所属页面
  • 所属链路
  • 是否总览指标
  • 指标方向
  • 基准口径
  • 预警阈值
  • 异常阈值
  • 权重
  • 诊断结论
  • 建议动作
  • 下钻页面

这样数据更新后，系统可以自动输出健康度、状态、Top问题、诊断结论和建议动作。
